# Audit — 2026-09 (Phase 0 verification)

**Scope:** confirm or refute the gap analysis in `AGENT-CHECKLIST-v1.md` §Phase 0
against the actual code at v0.1.0 (`39089fc`), read-only.
**Method:** static inspection of source, `manifest.config.ts`, `.size-limit.json`,
`.github/workflows/ci.yml`, and the built `apps/extension/dist/`.
**Result format:** one line per item: `CONFIRMED | REFUTED | PARTIAL — evidence (file:line)`.

> "CONFIRMED" means the concern described in the checklist exists in the code.
> "REFUTED" means the concern does **not** exist (the code already does the right
> thing, or the described condition is false). "PARTIAL" means part of the claim
> holds and part does not.

---

## Findings

- **0.1 — External password-form action override checks action-host Tranco membership — REFUTED.**
  `hardOverride` returns `MEDIUM` for _any_ external action and does not consult
  `in_tranco_50k` at all (`packages/heuristics/src/overrides.ts:15,20`). No action
  host is carried into scoring; `in_tranco_50k` encodes only the page eTLD+1
  (`packages/features/src/extract.ts:54-55`). Any external action forces MEDIUM.

- **0.2 — Rescue threshold `0.15` is a hardcoded constant, not read from `Settings` — CONFIRMED.**
  Literal `0.15` in `mergeVerdicts` (`apps/extension/src/background/scoring.ts:44`).
  `Settings`/`SettingsSchema` expose only `medium` and `high`
  (`apps/extension/src/background/settings.ts:3-20`); there is no `rescue`.

- **0.3 — On stage-2 timeout the code finalizes on stage 1, not `UNKNOWN` — CONFIRMED.**
  `finalizeOnTimeout` uses `state.stage1 ?? unknownVerdict()`
  (`apps/extension/src/background/service-worker.ts:69-77`). PRD §8 specifies
  timeout ⇒ `UNKNOWN` (`PRD-phishing-extension-v1.md:99`). Deliberate divergence to
  be recorded as an ADR in task 2.6.

- **0.4 — Features #37 `anchor_null_ratio`, #41 `copyright_brand_mismatch`, #42 `login_form_on_http` are always 0 — REFUTED.**
  All three are computed: `anchor_null_ratio` at
  `packages/features/src/dom/structure.ts:113-117`, `copyright_brand_mismatch` at
  `structure.ts:135-137`, `login_form_on_http` at `structure.ts:139-140`. Dead
  features from 0.4 are therefore none; task 2.9 has no extractor work.

- **0.5 — Does anything listen to `onCommitted` / `onHistoryStateUpdated` — PARTIAL.**
  An `onCommitted` main-frame listener exists but only `console.log`s the URL; it
  does not re-score (`apps/extension/src/background/service-worker.ts:85-88`).
  There are **no** `onHistoryStateUpdated` or `onReferenceFragmentUpdated`
  listeners anywhere. FR-1's `onCommitted` behaviour is effectively unimplemented.

- **0.6 — Sub-frame `SCORE_REQUEST` storage / `frameId` carriage — CONFIRMED (frameId is dropped).**
  `ScoreRequestPayload` has no `frameId` field
  (`apps/extension/src/shared/messages.ts:8-14`) and the content script sends no
  frame identifier (`apps/extension/src/content/content-script.ts:111-120`). The
  service worker keys state only by `sender.tab.id` and overwrites
  `stage2`/`final` unconditionally (`service-worker.ts:141-163`), so an iframe's
  stage-2 result clobbers the main frame's verdict.

- **0.7 — Cold-start readiness of Bloom filter and settings cache — CONFIRMED (no barrier).**
  `initSettingsCache()` is fire-and-forget at module load
  (`apps/extension/src/background/service-worker.ts:16`); `cachedSettings()`
  returns `DEFAULT_SETTINGS` until it resolves
  (`apps/extension/src/background/settings-cache.ts:3,13-15`). `runStage1` does not
  await any readiness. Worse, `runStage1` calls `extractStage1(url)` **without a
  bloom option** (`service-worker.ts:48`), so `in_tranco_50k` is always 0 in the
  extension (`packages/features/src/extract.ts:53-55`); the content script likewise
  calls `extractStage2` with no bloom (`content-script.ts:99`). Stage 1 can
  therefore score with an empty allowlist and an always-empty Bloom filter.

- **0.8 — Bloom filter shipped in `dist/` from real Tranco top-50k vs test fixture, and size vs 200 KB — REFUTED (none shipped).**
  `apps/extension/public/` contains only `icons/` and a 0-byte `model.bin`; the
  built `dist/` contains no `.bloom` file. The only Bloom artifact is the
  1,214-byte test fixture `fixtures/bloom/bloom.bin`. No code loads any Bloom into
  the extension. Shipped size: 0 bytes (budget 200 KB, N/A).

- **0.9 — Is `size-limit` enforced in CI, given the content-script bundle is over target — PARTIAL.**
  `pnpm size` runs in the `node` CI job (`.github/workflows/ci.yml:29`) and
  `size-limit` exits non-zero on regression, so the three configured budgets are
  enforced (`.size-limit.json:1-16`). However there is **no content-script budget**
  configured (only WASM ≤1 MB, `model.bin` ≤600 KB, total dist ≤3 MB), so the
  claimed 60 KB content-script target is not enforced; and the `model.bin` ≤600 KB
  budget is vacuous because that file is 0 bytes. Built content script:
  8.0 KB raw / 2.9 KB gzip, but it pulls the shared `messages` chunk at
  291.8 KB raw / 122.1 KB gzip.

- **0.10 — Which of `scripting`, `tabs`, `offscreen` are actually exercised — PARTIAL.**
  - `webNavigation` — used: `onBeforeNavigate` / `onCommitted` / `onCompleted`
    (`service-worker.ts:79,85,90`).
  - `storage` — used: `chrome.storage.sync` (`settings.ts:26,39,47`),
    `chrome.storage.session` (`tab-state.ts`), `chrome.storage.onChanged`
    (`settings.ts:71`).
  - `tabs` — the only real call sites are `chrome.tabs.query` (`popup/main.ts:29`),
    `chrome.tabs.remove` (`service-worker.ts:184`) and `chrome.tabs.onRemoved`
    (`service-worker.ts:99`). `tabs.query`'s `url` field is already granted by
    `host_permissions: <all_urls>`; `tabs.remove`/`onRemoved` require no permission.
    The `tabs` permission therefore appears redundant.
  - `scripting` — **not exercised**: no `chrome.scripting.*` call exists anywhere
    in `apps/` or `packages/`.
  - `offscreen` — **not exercised**: no `chrome.offscreen.*` call exists;
    `DEEP_SCAN` is a stub returning `UNKNOWN` (`service-worker.ts:189-190`).

- **0.11 — Do proceed/continue buttons check `event.isTrusted` — CONFIRMED (no checks).**
  No `isTrusted` reference exists in `apps/` or `packages/`. Interstitial and
  banner handlers attach plain click listeners
  (`content/ui/interstitial.ts:8-15,76-100`; `content/ui/banner.ts:8-15,48-50`).
  The service worker's `PROCEED`/`DISMISS`/`SET_ALLOWLIST` handlers accept either
  `sender.tab?.id` or an attacker-controllable payload `tabId` without verifying the
  sender is that tab's content script (`service-worker.ts:164-181`).

## Additional findings (not in the checklist, affecting Phase 1–2 tasks)

- **`in_tranco_50k` is always 0 in production.** No Bloom file is bundled and no
  caller passes `options.bloom` to `extractStage1`/`extractStage2`
  (`service-worker.ts:48`, `content-script.ts:99`). This silently breaks a feature
  the training data will not show as always-zero, and it makes the PRD §10.4
  action-host override (task 2.1) unimplementable until loading lands. Task 2.4
  must load and await the Bloom, not just the settings cache.

- **`apps/extension/public/model.bin` is 0 bytes.** It is a placeholder; the
  `size-limit` `model.bin ≤ 600 KB` budget currently passes trivially (task 4.6).

- **Built `web_accessible_resources` is non-empty** (crxjs content-script loader
  chunks are exposed) per ADR #3 (`docs/DECISIONS.md:43-53`); no
  `use_dynamic_url` is set. Relevant to task 1.5.

- **`docs/OPEN-QUESTIONS.md`, `docs/EVAL.md`, `docs/MODEL-FORMAT.md` do not exist.**
  `docs/` currently holds only `DECISIONS.md`, `INSTALL-TESTERS.md`, `LATENCY.md`.

- **`README.md` is untracked** in git at the start of this work; the per-task
  README deltas will bring it into version control.

## Phase 1–2 task adjustments

- None of items 0.1–0.11 were REFUTED in a way that lets a task be skipped, **except
  task 2.9**: item 0.4 is REFUTED (all three "dead" features are computed), so
  **2.9 has no missing extractors to implement**. It collapses to verifying the
  golden fixtures already cover #37/#41/#42 (they do — see
  `fixtures/golden/dom/`), plus a README accuracy check.
- Task 2.4 is **expanded**: it must load/await the Bloom filter as well as the
  settings cache, and route the loaded Bloom into both `extractStage1` and
  `extractStage2` (see additional findings). Without this, `in_tranco_50k` and the
  2.1 fix cannot function.
- Task 2.3 covers the missing `onHistoryStateUpdated`/`onReferenceFragmentUpdated`
  work implied by item 0.5.
- Task 4.1 is confirmed necessary (`scripting`, `offscreen`, likely `tabs` removable).
